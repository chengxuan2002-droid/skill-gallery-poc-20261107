# Handoff Codex

长会话结束前生成一份交接文档，让下一次会话（或接手的人）能快速接上进度。

## 何时使用

- 即将结束一轮多轮对话，手头还有进行中的工作
- 用户明确说 handoff / 交接 / 保存进度 / 记录一下
- 暂停复杂工作，稍后再继续
- 任务做到一个自然的停顿点

## 工作流程

1. 确定项目根目录 —— 通常是当前工作目录。不确定就问用户。
2. 运行脚本创建文件：
   ```bash
   bash "$SKILL_DIR/scripts/create_handoff.sh" project-root
   ```
   脚本会创建 `handoff/` 目录和 `handoff-YYYYMMDD-HHMMSS.md` 文件，并输出文件路径。
3. 打开生成的文件，用当前对话的具体信息填充每个章节。
4. 向用户确认已创建的文件和位置。

## 写作指南

具体、事实。每个章节都要有可操作的信息，而不是模糊的总结。

### 1. 现在做什么

- 当前正在进行的具体任务或目标
- 哪些文件正打开 / 正在编辑
- 当前采用的方法或策略
- 接手的人马上需要知道的上下文

### 2. 已经完成了什么

- 已完成的工作项，带文件路径，不要感受
- 关键决策及其原因
- 提交、分支、或产出的文件
- 跑过的测试及其结果

### 3. 卡在哪里

- 确切的阻塞点或待解决问题
- 试过但不奏效的方法
- 不确定或未知的地方
- 缺少什么信息

### 4. 下一步做什么

- 有序的下一步行动列表
- 优先级很重要
- 每一项要具体到让一个刚接手的人知道该做什么

### 5. 哪些坑不要再踩

- 已经探索过的具体错误或死路
- 环境配置的陷阱
- 看起来能行但实际不行的事
- 任何不明显的行为或配置

## 注意事项

- 默认用中文写；如果对话是英文的就切英文
- 简洁但完整：优先用要点和具体细节，不用大段散文
- 有帮助的地方加上文件路径和行号
- 不要跳过任何章节 —— 如果某节是空的，写"无"或"暂无"并简要说明原因
- 写多了比写少了好
